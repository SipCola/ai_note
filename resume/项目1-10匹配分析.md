# 项目组合样例（5 条）

> 素材来源：`项目1-10.md`（13 个候选项目）、`备选公司.md`（业务背景参考）、`修改简历注意事项.md`（项目分类框架）
> 组合原则：基础设施（任何公司都要）+ 通用业务（任何公司都要）+ 与目标公司业务贴合的业务项目，共 5 条。每条约 300 字。

---

## 样例一 ｜ 电商私域 / 直播带货方向（医疗器械、保健食品、跨境母婴、护肤独立站）

**适配对象**：优贝施、美兰、金蔻、美瑞可、采活医药、百菌健堂、优壹电子商务、健汲网络、Swisse、杭州民生健康。
**项目顺序**：01 评测监控中台 → 03 AI 数据中台 → 02 实时语音客服 → 04 直播切片 Agent → 07 素材中心 + 销售考核

**组合侧重点**
- 这类公司共同的组织形态是「导购 / 导购群 + 小程序或独立站 + 私域直播」，简历四条主线要能对上「导购话术沉淀、商品资料检索、直播内容复用、新人培训」四个真实痛点。
- 数据中台打头：微信 SQLite → raw_chats → DataFilter 脱敏 → staging 人工审核 → RAG CSV/ShareGPT 多格式导出，正好讲清「把导购三年聊天记录变成可检索、可训练资产」；价格脱敏设为硬红线（清洗/写入/导出三次）是这类公司的强合规信号。
- 客服接多模态：命中图/视频以「文字 + 图片 + 视频」混排分条返回，语音链路 TTFT 15s→2s，对应售前导购「发图即答、秒回」。
- 直播切片：FFmpeg.wasm WORKERFS 零拷贝，2.5GB 压到 ~30MB（体积降 99%），爆款分 + 抖音风标题，直接解决素材生产。
- 考核系统用中台 knowledge_articles 自动出题、五维打分，把「新人培训」从人工搬到线上。

**写作要点**：业务背景统一写「某消费品电商私域 / 直播场景」，不点真实公司名；营收类数字一律不写，只写技术指标（召回率、TTFT、压缩比、评测通过率）。

## 样例二 ｜ 健康 / 医疗大健康方向（体检、口腔、医美、健康管理、制药基因）

**适配对象**：倍泰健康、大连源康、爱丽斯医美、维密欧贝丽口腔、思创医惠、采活 / 卫宁沄钥 / 泰安堂药房、北大未名、科泰基因。
**项目顺序**：05 医疗 Harness 底座 → 08 医疗 Agent 质量评测平台 → 09 健康商品知识库（RAG）+ 咨询 Agent → 06 处方 / 说明书合规审核 Agent → 02 多模态影像 / 报告解读

**组合侧重点**
- 医疗类公司对 AI 的第一诉求不是「快」而是「错不了」，所以 Harness 承压能力（审计留痕、降级转人工、AI 免责声明）与评测门禁要前置；按 `注意事项` 的医疗命名思路复用「项目 3 Harness 框架设计」「项目 10 质量评测与回归验证平台」的包装。
- 商品/服务知识库：药品说明书、器械注册证、术后护理 SOP 按章节语义切分；同款多规格、多包装版本、不同渠道口径分开过滤，命中必须带来源引用与有效期。
- 合规审核 Agent：处方 / 广告用语 / 红线禁词三级校验，价格与疗效话术不暴露；工具做 R1–R3 风险分级，R3 强制人工确认并落审计日志。
- 评测：真实咨询日志脱敏沉淀用例 + 事故用例 + 红队用例，RAG 层 / 模型层 / Agent 层三层定位，「任一场景跌幅 > 5 分即阻断」。
- 影像与报告方向（联系医院或体检公司时）：超声 / X 光 / 报告文本结构化入库（把 `注意事项` 里的「影像 RAG 管控中心」按合规重建），输出只做辅助提示。

**写作要点**：合规话术必须真实可信；不写数据出境、不写跨境传输；「模型训练」涉及患者数据时改写成「脱敏数据 + 人工复核」的评测集建设。

## 样例三 ｜ AI 工程效能与 Agent 基础设施方向（技术平台、云厂商、通用大厂）

**适配对象**：任何做 AI 应用落地的公司，尤其互联网、金融科技、SaaS 厂商（本批清单里无此类公司时，用作通用版）。
**项目顺序**：09 Harness 底座 (Agent Loop) → 06 MCP 多 Agent 共享服务集群 → 01 评测监控中台 → 02 研发流程效能提升 → 08 微调（作为 RAG 之外的备选）

**组合侧重点**
- 这条线是 `注意事项` 分类里的「基础设施」，面试官看的是抽象能力而不是业务描述，所以术语密度要拉满、业务背景一句话带过。
- Harness：LLMProvider + Tool 双抽象 + 注册表，模型无关、工具可插拔；model-driven 自主循环替代 workflow 编排；「错误即上下文」自纠错；最大步数 + 超时护栏降级转人工；Trace 可视化决策链路。
- MCP 集群：4 个 Server（LLM 网关 / RAG / 记忆 / Prompt）+ REST→MCP 桥接，四层中间件（认证→日志→配额→路由），Trace ID 全链路；虚拟 Key 三级配额与成本归因。
- 评测中台：7 维评估模型 + 5 层架构，「80% 代码断言 + 20% LLM 裁判」、三级分级裁判降 Token 成本；CI/CD 质量红线拦截「智商倒退」。
- 研发流程：Context as Code（AGENTS.md + .cursor/rules + Skills）、Spec 驱动开发、git worktree 并行编队（单人 3–5 Agent 的甜蜜点）、三层门禁。
- 一句话把整条线钉在「可观测、可评测、可回滚的 AI 生产系统」上。

**写作要点**：动词用「抽象 / 收口 / 沉淀 / 治理」，指标用「成本 -40%、TTFT -60%、定位小时级→分钟级」；不要写公司内部流程细节（如 PR 模板），只讲工程纪律。

## 样例四 ｜ 内容与营销增长方向（品牌方、MCN、内容电商）

**适配对象**：美兰 / 优贝施（小程序商城 + 直播）、巨悠欣苷（天猫 + 小红书）、雅拉源优思益（抖音旗舰店）、健汲（私域直播团购）。
**项目顺序**：05 自媒体智能内容 Agent → 04 直播切片 → 07 素材中心 → 03 数据中台 → 02 客服（素材回流闭环）

**组合侧重点**
- 这类岗位关心「同样的钱能不能多出内容」，顺序要把内容生产放前面、数据底座放后面（和样例一的顺序区分开，突出不同侧重）。
- 内容 Agent：LangGraph SubGraph 拆选题 / 写作 / 配图，PostgreSQL Checkpointer 支持节点级回滚；SSE 流式 + `astream_events` 把感知 TTFT 降 60%；配图 asyncio.gather 并行、指数退避重试，整体耗时 -70%；轻量 Flash / 旗舰双模型路由，推理成本 -40%。
- 切片：进度统一写库 + SSE 每秒读库推送（断线可续、多端一致）；长音频按 25 分钟 `-c copy` 分段串行转录、时间戳加 offset 还原绝对时间轴；6000 token 分批 + 重叠去重 ≥30% 取高分。
- 素材中心：不向量化媒体本身、只向量化 retrieval_text（「这张图能回答什么问题」）；OCR + VLM + ASR 离线增强让召回相似度 0.38→0.71。
- 收尾点「生成即沉淀」：AI 出的商品图进素材中心、客服直接调用、直播片段进知识库，形成内容资产复利。

**写作要点**：通篇讲「产出效率」与「素材复用率」，不要出现大段技术栈罗列；每个项目只留 2–3 个杀手指标，避免简历像技术文档。

## 样例五 ｜ 销售转化 / 私域运营方向（任何有销售团队的公司，非技术岗友好版）

**适配对象**：保健食品经销（如百菌健堂一类的授权专卖店模式）、连锁药房、医美 / 齿科的销售顾问团队、教育或课程销售；也可作为对「AI 产品 / 解决方案 / 售前」岗位的投递版。
**项目顺序**：01 销售考核 Agent → 09 商品交易自进化 Agent（示范学习）→ 03 数据中台 → 02 客服 → 01 评测（少技术、多业务语言）

**组合侧重点**
- 这条线要做到「不懂代码的 HR 也能读懂」：先讲业务结果（培训周期、话术一致性、成交引导），技术名词只保留必要的几个。
- 销售考核 Agent：从 approved 知识自动出题（简单/中等/困难），「资深评审专家」五维打分（实战性 / 需求把握 / 销售策略 / 话术自然度 / 红线检查），百分制，支持人工复核校准。
- 自进化 Agent：示范学习替代微调——专家「问题 + 标准答案 + 套路原因」教学 → LLM 归纳套路总纲 → 注入提示词；状态合并时冲突以人工为准；答不上→工单→专家补充→入库→下次答对的自纠错闭环。
- 数据中台与客服：价值说成「导购聊天记录变教材」「新人对答如流」「客户问图能秒回」。
- 评测只保留一条：线上翻车案例转回归用例，「不在同一个地方跌倒」。

**写作要点**：把「微调、RAG、Harness」等词压到最少的必要处；多写「谁受益、好在哪里」；如果投销售类岗位，还要补一句「本人具备 XX 年销售 / 团队管理经验」，否则整条线会被读成纯技术岗。
