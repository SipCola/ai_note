## 零、一句话总览

**两件事、一条数据线**：素材中心统一管理商品图/详情/视频，为 AI 客服提供多模态回复能力，同时补充数据中台；中台导出的高质量知识又驱动 AI 销售考核，替代过去的人工培训。

- **项目定位**：属于**业务层面的挂件项目**，技术上没有难点，核心价值是**打通全流程，让项目故事更完整、更丰富**。
- **数据来源两条通道**：① 人工上传的图片/文字/视频；② 自媒体运营 Agent 生成的图片/文字（还可扩展生成视频）。
- **面试核心**：不是讲技术难度，而是讲**业务流程整合**——素材中心 → 数据中台 → AI 客服；数据中台 → RAG → 销售考核。

# A. 多模态素材中心

## 一、要解决的问题

- 早期数据中台清洗聊天记录时，里面的图片、视频基本都被当成脏数据洗掉了。
- 但业务上希望在对话中，用户问一件商品时能自动回复**图片**以及**商品视频介绍**。
- 所以单独建了 AI 素材管理中心：把商品图片、视频上传进去，与数据中台打通，数据就能提供给智能客服去回复文字、图片、视频。

## 二、统一向量底座 `rag_assets`

### 2.1 设计

- **text / image / video 三模态共用一张表**，一条 SQL 跨模态召回。
- 技术选型：**pgvector 1024 维 + HNSW `vector_cosine_ops`** 索引。
- **核心理念：不向量化媒体本身，而是向量化它的「检索文本」`retrieval_text`**——即"这张图/视频能回答什么问题"，与用户文本提问天然对齐。

### 2.2 为什么这么设计（面试点）

- 用户是**用文字提问**的，图片和视频本身没法直接与文本做语义对齐；把它们转换成"这段素材能回答什么问题"的文字再去向量化，效果最好。
- 三模态共用一张表，检索时一条 SQL 就能跨模态召回，工程上简单、一致。

## 三、两条入库路线

### 3.1 人工即时命中（manual）

- 图片/视频**上传时**由人工维护**标题/描述/标签/分类**，拼接为 `retrieval_text`，经 `text-embedding-v3` 向量化入库即可被命中。
- **隐私红线**：命中返回的是**打码版 TOS URL**。

### 3.2 离线机器增强（enriched）

- **在同一行上**：用 **OCR（RapidOCR）+ VLM（qwen-vl）** 补图片文字与"看图描述"；用 **ASR + LLM 摘要**补视频口播。
- **拼接策略**：**人工内容在前、机器内容追加**，重写 `retrieval_text` 并重新 embedding。
- **效果**：召回相似度从 **~0.38 提升至 ~0.71**。
- **幂等**：按 `(source_table, source_id)` **UPSERT**，可反复回扫。

### 3.3 两条路线对比

| 对比维度 | 人工上传素材 | AI 生成素材 | 离线增强素材 |
|---|---|---|---|
| 来源 | 运营人员手动上传 | 自媒体 agent 自动生成 | 直播切片 + 离线大模型 |
| 处理方式 | 人工编写描述 → 向量化 | 自动生成文案 → 向量化 | ASR 转写 → 离线摘要 → 向量化 |
| 成本效益 | 人工成本高、效率低 | 自动化、成本低 | 需离线任务调度，批量处理效率高 |
| 搜索命中率 | 依赖人工描述质量 | 依赖生成文案质量 | 摘要含价格/卖点，命中率高 |

## 四、长视频分段与统一应答策略

### 4.1 长视频分段

- 按 **ASR 时间戳**将长视频分段为**多条 `rag_assets`**；
- `media_url` 携带 **`#t=秒数`**，命中后前端播放器**直接跳转到精彩片段**。
- 长视频分段属于**直播切片（项目三）的功能延伸**——同一个视频会被拆成多条素材，每条对应一个精彩片段。

### 4.2 统一应答策略

- 按「**文字必发、图 ≤3、视频 ≤1**」混排；
- 阈值递增：**text 0.35 < image 0.40 < video 0.42**。
- 含义：视频/图片的相似度门槛更高（因为素材曝光成本更高、误召回代价更大），文字必发保证兜底。

## 五、离线增强（直播切片 → 素材中心）

- **定义**：利用**离线大模型任务**自动生成视频描述，替代人工编写。
- **实现流程**：
  1. 直播切片通过 **ASR** 转出完整文字（1~2 分钟）；
  2. **离线大模型任务**对完整文字写摘要；
  3. 摘要作为**视频的备注描述信息**，确保包含**商品价格、特点、卖点**等关键信息；
  4. 将摘要添加到备注描述信息中，用户搜索时即可命中。
- **价值**：不用人工去写视频的描述；摘要含价格/卖点，命中率高。

## 六、多模态检索流程（与项目一打通）

1. **意图识别**：判断用户需要文字、图片还是视频回复；
2. **Query 改写**：对用户查询改写，提升命中率；
3. **向量检索**：通过向量数据库（ANN）分别检索文字、图片、视频。

实现原理：图片和视频的存储结构与文字一致——**商品信息 + 描述向量化，额外多一个 URL 字段**；返回前端的是 **URL**，前端据此加载资源，**通过文字描述去命中，而不是解析图片或视频本身**。

常见误区：认为"多模态检索是直接理解图片内容"——实际是**转文字命中**。

## 七、与其它项目的联动

| 上游 | 流向 | 下游 |
|---|---|---|
| 人工上传 + 自媒体 Agent 生成 | → | 素材中心 `rag_assets` |
| 直播切片（ASR 文本）→ 离线摘要 | → | 视频素材（含价格/卖点） |
| 素材中心（图片/视频/文字） | → | 补充**数据 A**，服务 AI 客服（项目一） |
| 素材中心 | → | 数据中台（项目二） |

# B. AI 销售考核系统

## 八、要解决的问题与定位

- **定位**：替代人工培训与考核，由数据中台导出的高质量知识驱动；可以理解为"**AI 销售系统**"，核心作用是**培训 + 考核**。
- 公司有大量私域销售，需要培训与考核；数据全部来源于数据中台的真实聊天对话，以及人工补充的业务信息。

## 九、销售培训：直接看原始聊天记录

### 9.1 核心方法

- 系统页面**左侧是会话列表，右侧展示完整的对话信息**。
- 数据中台对微信数据进行清洗（ETL），根据不同业务导出不同数据。
- **给销售看的数据必须包含产品价格、成本、底价等关键信息**，否则销售无法回答客户"400 能不能卖"这类问题，容易导致亏损。

### 9.2 重要原则

> **培训必须看原始数据，AI 清洗或大模型改写过的内容"纯扯淡"。**

- 改写后的数据失去了"人味"，AI 味过重，对销售来说反而是误导。
- 这是本项目一个非常"反常识"但真实的业务原则，面试可以当亮点讲。

| 对比项 | 原始数据培训 | AI 清洗后培训 |
|---|---|---|
| 真实性 | 高（保留人味） | 低（失去人味） |
| 销售实用性 | 极强（直接可用） | 弱（纯扯淡） |
| 数据开放度 | 高（含价格、成本） | 低（过滤关键信息） |
| 培训效果 | 有效 | 无效 |

## 十、销售考核：出题 + 打分 + 交卷

- **考核方式**：系统自动**出题、打分、交卷**，考察销售的**思路**——根据销售与客户的真实对话记录，考核其应对策略是否合理。

### 10.1 AI 出题的局限

- **核心结论：AI 不擅长直接出题**，需要人工介入大量操作，尤其是面对**十万级题库**时。
- **真实数据 vs 试卷的差异**：
  - 真实场景：用户问"课多少钱？"，销售回答"咨询班主任"并返回微信二维码。
  - 考试场景：题目需要**交代上下文**（如"假设一个大专生问课多少钱"），答案需体现**思路**（如"先塑造价值，不能直接说价格"）。
  - 关键矛盾：直接让知识库匹配"真实对话"和"考试答案"，评分会非常低，因为真实回答（先塑造价值）与知识库直接匹配不上。

### 10.2 出题架构设计（三步）

1. **题目打标签**：将题目分类为**价格咨询、情况咨询、产品特点、团队优势**等。
2. **出题列大纲（LLM 介入）**：根据标签规划题目结构，例如"成交类出 3 题，产品特点出 2 题，团队介绍出 2 题"。
3. **根据大纲和标签去数据库找题**：题目存储在 **MySQL** 等数据库中，根据标签过滤后**随机挑选**。
- **核心思路**：通过标签把**十万道题目过滤到几百道**，再从中随机挑选，解决题库膨胀问题。

### 10.3 评分侧设计

1. **评分规则制定**：必须包含对**销售思路的判断**，而非仅匹配答案文字。
   - 示例：真实数据是"咨询销售微信号"，但考试答案"先塑造价值，不直接说价格"是正确的，评分规则需识别这种沟通思路。
2. **Query 改写**：对用户的作答进行改写，包括**修正错别字、识别沟通思路**。
   - 目的：让用户的作答 query 能更好地命中 RAG 知识库中的题目。
   - 示例：题目"你的课多少钱？该怎么回答？"需通过意图识别，改写为更贴近知识库标题的表述。
3. **意图识别**：将考试题目和用户回答都转化为**更易命中 RAG 的文案**，提升评分准确性。
4. **评分**：查询 RAG，更好地命中知识库的题目，再逐题打分。

### 10.4 业务调整（加分点）

- **让考试过程模拟真实用户对话**，而非写试卷式的"我是这么想的"，使回答与 RAG 知识库更友好，提升命中率。
- 作答展示形式：

```
题目：你这个课多少钱？
背景：这是一个大专生，之前它说过 xxxx
作答：大专当然可以学呀，我们有 xxxx 案例
```

### 10.5 简历版的 LLM 出题/评判口径

- **LLM 自动出题**：消费数据中台产出的 `knowledge_articles` / `knowledge_chunks`，按**场景分类 + 置信度**取素材，以「**资深考官**」角色（**temperature 0.7**）生成**简单 / 中等 / 困难**分级的开放式场景题与参考答案。
- **LLM 自动评判**：以「**资深评审专家**」角色（**temperature 0.3** 保稳定）从 **实战性、需求把握、销售策略、话术自然度、红线检查** 五个维度逐题打分，按「**平均分 ×10**」映射**百分制**，支持**人工二次复核校准**。

### 10.6 知识库膨胀到十万级的演进：RAG 出题方案

- 模糊请求先由 LLM **规划主题** → **多轮向量检索**（pgvector / Milvus）→ **MMR 去重保多样性**；
- 解决**固定 top-30 导致题目重复、长尾素材浪费**的问题。

## 十一、数据库与 RAG 分别怎么设计（面试常问）

题目与评分在设计上是两条线：

| 部分 | 载体 | 关键设计 |
|---|---|---|
| 题库（出题侧） | **MySQL 等数据库** | 题目标签（价格咨询/产品特点/团队优势…）+ 大纲随机抽取；标签过滤是核心，避免全量检索低效 |
| 评分（评分侧） | **RAG 知识库** | 把题目和答案统一改写为"易命中"的表述；意图识别 + Query 改写双过滤，确保评分准确 |

- **流程**：出题侧（标签 → LLM 大纲 → 按标签随机取题）→ 考试作答（模拟真实对话，带背景）→ 评分侧（意图识别 + Query 改写 → 查 RAG → 五维打分 → 百分制）。
- 作业提示："详细地了解如何设计一个考试系统（出题 + 考试）；数据库和 RAG 分别如何设计？流程是什么？"这是官方指定的追问方向。

## 十三、高频面试问答速记

**Q1：素材中心为什么建？**
A：数据中台清洗聊天记录时把图片视频都当脏数据洗掉了，但客服回复商品时需要图片和视频介绍。所以单独建了素材中心统一管理商品图、详情、视频，跟数据中台打通后供客服回复文字/图片/视频。

**Q2：图片和视频怎么被语义检索到？**
A：不向量化媒体本身，向量化它的"检索文本"——也就是"这张图/视频能回答什么问题"。三模态共用 `rag_assets` 一张表，pgvector 1024 维 + HNSW cosine，一条 SQL 跨模态召回。用户用文字提问，天然对齐。

**Q3：为什么一条 SQL 能查三种模态？**
A：因为三者存的是同一种东西——检索文本的 embedding，只是媒体类型和 URL 不同。

**Q4：人工维护和机器增强怎么相处？**
A：两条路线。人工路线是上传时维护标题/描述/标签/分类，拼成 retrieval_text 直接入库；机器增强路线是在同一行上用 OCR + VLM 补图片文字和看图描述、用 ASR + LLM 摘要补视频口播，人工内容在前、机器内容追加，重写 retrieval_text 重新 embedding，相似度从 0.38 提到 0.71。按 source_table + source_id UPSERT，可以反复回扫，幂等。

**Q5：视频很长怎么办？**
A：按 ASR 时间戳切成多条 rag_assets，media_url 带 #t=秒数，命中后前端播放器直接跳到精彩片段。

**Q6：为什么阈值 text < image < video？**
A：素材曝光成本更高，图片视频误召回代价更大，所以门槛逐级抬高；文字必发保证兜底。

**Q7：隐私怎么保证？**
A：命中返回的是打码版 TOS URL。

**Q8：销售培训怎么做的？**
A：直接看原始聊天记录——左边会话列表、右边完整对话。数据中台对不同业务导出不同数据，给销售的数据必须包含价格、成本、底价，否则他没法回答"400 能不能卖"。**AI 改写过的内容反而不给销售看，因为没有"人味"，纯扯淡。**

**Q9：考试系统怎么设计？**
A：出题侧——题目打标签（价格咨询/产品特点/团队优势），LLM 出大纲（成交 3 题、产品特点 2 题…），再按标签从 MySQL 随机抽题，把十万级压到几百道。评分侧——先定评分规则（要判思路，不是比文字），再做意图识别 + Query 改写（修正错别字、识别沟通思路），让题目和答案都能更好命中 RAG，最后逐题打分。

**Q10：为什么 AI 不适合直接出题？**
A：真实对话和考试答案不是一回事——真实场景销售回答"咨询班主任"加一个二维码，考试要考的是"先塑造价值，不能直接说价格"。直接让知识库匹配，评分会非常低。所以 AI 更适合出大纲、做辅助，真正的题目标签和思路要人工定。

**Q11：十万道题怎么办？**
A：靠标签过滤 + 大纲随机抽，而不是全量检索；后续演进成 RAG 出题，LLM 规划主题 → 多轮向量检索 → MMR 去重保多样性，避免固定 top-30 导致题目重复、长尾素材浪费。

**Q12：为什么考试要模拟真实对话而不是写试卷？**
A：写试卷式的"我是这么想的"和知识库对不上；改成模拟真实用户对话（题目 + 背景 + 作答），回答与 RAG 知识库更友好，命中率更高。

## 十四、易混淆点自查

- 素材中心**不是技术复杂项目**，核心价值在业务流程整合与数据闭环。
- 图片/视频是**转文字命中**，不是解析媒体本身。
- 检索文本 = "这段素材能回答什么问题"，不是媒体内容描述本身。

- 出题靠**标签 + 大纲 + 数据库随机抽**，不是全靠 LLM 生成。
- 打分要判**思路**，不是判答案文字。
