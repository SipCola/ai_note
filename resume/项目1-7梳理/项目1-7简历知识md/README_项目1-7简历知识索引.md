## 一、8 个项目怎么串成一条线（来自讲义 02、03 与参考话术）

**一段话版自我介绍**：

> 我之前在一家做 3C/电商的公司，业务有海外独立站、TK、亚马逊，我是 AI 部门负责人。过去几年做全栈开发，后来发现 AI 在电商领域能极大降本增效，就向老板提议做 AI 生态体系。我们是这么一步步做的：

1. **项目一 AI 实时语音对话客服**：最开始做的项目。海外客户从独立站引流到 WhatsApp/销售微信，我们用真实聊天记录导出、人工清洗后建 RAG 知识库，做了支持语音对话的智能客服。
2. **项目二 数据中台**：每次都要程序员导数据太麻烦，为了让运营/销售自己就能导出清洗，做了数据中台，原始数据进来、清洗后导出 RAG 格式供客服使用。
3. **项目六-A 素材中心**：聊天记录里的图片视频原来都当脏数据洗掉了，但客服回复商品需要图片和视频，于是做了素材中心，并与数据中台打通。
4. **项目四 自媒体运营 Agent**：素材中心建好后，让运营用 Agent 生图、生视频，生成的素材与素材中心关联；商品主图和介绍视频后来基本都由 AI 生成。
5. **项目六-B 销售考核**：公司有大量私域销售，用数据中台的数据建 RAG，让 AI 做培训和考核。
6. **项目三 直播切片**：TK 主播直播后要切片，AI 自动找高光片段，切完筛选后与素材中心关联，再提供给数据中台和客服系统。
7. **项目七 模型微调**：数据越来越多，把中台数据导成 SFT/DPO 格式做微调，让模型回复更像真实销售，微调后的模型用于 AI 实时语音对话。
8. **项目五 MCP 集群**：项目多了以后，把大量通用的 MCP 服务和 Agent 服务抽离成公共服务集群，支撑整个体系运行。

## 三、关键数字速查（全部出自讲义，可直接背）

### 项目一

- 数据量：10 万 → 2 万 → 2000 → 2000~2500 条，对应 20~30 款商品，平均每款约 100 条
- 向量维度 1024，2500 条 ≈ 10MB
- K=15、N=3；海选 K=20（评测）、K 可放到 25
- 召回率及格线 80%，商用线 95%~98%
- TTFT 15s → 2s（链路完整口径 15s → 1.5s）
- temperature：意图识别 0，客服回复 0.3
- max_tokens = 800；软限制"回复不超过 200 字"
- Redis 相似度缓存命中阈值 95%，缓存 Top N（3 条），TTL 5 分钟 / 1 小时 / 1 天
- RPM：默认约 500，可扩到 1000~2000；2 万 RPM 用多账号
- RTC：50% 丢包、Jitter Buffer 缓存 30~50ms

### 项目二

- 5 个销售 × 人均 2 万条 = 10 万条 → 机器清洗 2 万 → 人工 2000 → 补充 100~200 → 2000~2500 条
- 5 分钟时间窗切分会话；9 级优先级分类；三次冗余脱敏
- 导出格式：ShareGPT / Alpaca / OpenAI JSONL / RAG CSV
- 向量化模型：DashScope text-embedding-v3

### 项目三

- 2.5GB → 约 30MB，上传体积降 99%
- 16kHz / 单声道 / 64kbps MP3
- 视频处理约 10 分钟/个；同时 100 个视频，QPS < 100
- 长音频 `ffmpeg -c copy` 按 25 分钟分段
- LLM 按约 6000 token 分批，重叠 >30% 取高分项；支撑 6 小时长视频
- 切片时长通常 5 秒 ~ 1 分钟（示例 1s~80s）
- 一场 2~3 小时直播，约 15 分钟切出 20~30 个视频

### 项目四

- 指数退避 1s → 2s → 4s；限流 `5/min`
- TTFT 降 60%；生成耗时降 70%；推理成本降 40%；调试效率提升 3 倍
- 熔断：10 次调用挂 5 次断开，半开每 5 分钟探测一次
- 计价：豆包 pro 输入 3.2 / 输出 16 元每百万 token；Seeddream 0.20~0.25 元/张；Seedance 约 1 元/秒（mini 约 0.5 元/秒）

### 项目五

- 8 个项目、几十到上百个 MCP 服务；每个项目仅能调授权范围内的 ~20 个
- 通用服务判定标准：3 个及以上系统共用

### 项目六

- `rag_assets`：pgvector 1024 维 + HNSW `vector_cosine_ops`
- 召回相似度 0.38 → 0.71
- 应答策略：文字必发、图 ≤3、视频 ≤1；阈值 text 0.35 < image 0.40 < video 0.42
- 出题：temperature 0.7；评判：temperature 0.3，五维度、平均分 ×10
- 题库十万级 → 标签过滤到几百道

### 项目七

- 本地：LLaMA-Factory + Qwen2.5-3B/7B，QLoRA（rank=64, alpha=128, lr=2e-4），4090 约 40 分钟/轮
- 云端：火山方舟豆包 1.6，LoRA（rank=32, lr=1e-5）；另有 lr 5e-5~1e-4 口径
- 数据量：本地 SFT 300~500 / DPO 100~200；云端 SFT 2000~5000 / DPO 500~1000
- 参数：本地 epochs 3~5、batch 1~2；云端 epochs 2~3、batch 8~16；Alpha = 2 × Rank
- Max Length 建议 4096
- 验收：本地盲评 2 → 4 分以上；云端胜率 > 80%、盲评接近 4.5 分灰度上线

## 五、讲述纪律（来自讲义 01、08、26 的面试策略）

- **"吹"不等于编**：面试本质是"在心里搞个项目"，关键是抓住核心概念、能讲清原理和取舍，而不是现场写代码。
- **抓主要矛盾**：意图识别 → 系统提示词 → RAG 检索 → 结果不会有大误差，讲清这套就够用。
- **辩证回答**：面试是辩证的过程，要能讨论不同方案的优缺点（pgvector vs 专用向量库、Rerank 用或不用、消息队列用或不用）。
- **指标要能解释口径**：解释不了口径的指标就改弱成"项目中观测到/团队口径"，否则删掉。**不要写具体指标**（如"召回率 50%→80%"）以免被追问评测集。
- **技术是臭狗屎**：技术为业务服务，先讲架构、再讲业务、最后讲扩展。
- **转移注意力**：被追问细节时，主动引导回"整体架构和业务背景"，展示架构思维。
- **不确定的地方诚实兜底**：可以说"这块我主要负责 X，Y 是同事做的，我了解接口和取舍"。

## 六、简历里"讲义没讲透"的词，先对好口径

以下几个词**只出现在简历/课件表述里**，44 份讲义没有展开，被追问概率高。详细解释写在 [项目一](项目一_AI实时语音对话智能客服.md) 的「十二·补」，这里先给结论：

| 简历用词 | 材料内的等价说法 | 安全口径 |
|---|---|---|
| 自定义标识符切片 | Markdown 标题层级 + 段落边界切分 / ASR 时间戳分段 | "不用固定字数硬切，按业务天然边界（一轮问答/同话题/时间戳）切块，保证不截断语义" |
| HNSW_HYBRID 混合检索 | 稠密+稀疏混合索引（火山 VikingDB 的 `hnsw_hybrid`，需有 sparse_vector 字段，可用 bge-m3 生成） | "混合检索检索侧我们用 pgvector 向量检索 + PostgreSQL 全文检索加权融合模拟；HNSW_HYBRID 是向量库侧的索引类型" |
| Int8 量化 / 存储降 75% | int8 把 float32 的 4 字节压成 1 字节，理论上省 75%，精度损失 2~3% | 注意与讲义 09"本项目不需要量化"冲突，见项目一第六、十二章 |
| Prompt Pilot | 项目五的 MCP Prompt 模板服务 + 评测集版本对比 | "提示词版本化平台：有版本、有评测集、能对比、能回流负样本，不是硬编码" |
| Max Token 按 95% 覆盖率 | 软限制（提示词"不超过 200 字"）+ 硬限制（`max_tokens=800`） | "统计历史回复长度，95% 落在某个区间内，就按这个边界配兜底 + 提示词引导短回复" |
