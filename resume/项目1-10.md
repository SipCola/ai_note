# 项目1： Agent 自动化评测与监控中台 (Agent Evaluation Middleware)

> 这个放在项目一

1. 多维度全链路评测体系架构设计：首创涵盖任务成功率、工具调用精度、上下文记忆对齐、Rag召回率、业务规则遵循、异常容错、成本时延及安全合规的 7 维评估模型，彻底替代传统“凭经验调 Prompt”的盲目迭代模式。（7个维度+5层架构）
2. LLM混合判定引擎（Hybrid Evaluation）：创新落地“80% 确定性代码断言 + 20% LLM 裁判”架构。利用 Python 状态快照与 Mock 数据库对工具参数、购物车前后置状态进行硬核校验；引入分级裁判策略，针对常规对错判定动态下放轻量模型，大幅降低大规模用例回归的 Token API 成本。3层分级裁判，逻辑=> 轻量 => 旗舰。
3. 百级用例递归调度与沙箱隔离：设计递归扫描式批量调度引擎（runner.py），支持 100+ 复杂测试用例按业务模块分层管理与一键全量跑测；配合独立的 Mock 数据库与状态重置沙箱，确保测试环境的高度隔离性与可重复性。
4. 双层报告与微观 Trace 溯源追踪：实现分级报告生成机制（reporter.py），宏观层输出包含总体胜率及多维失败分布的 CI/CD 大盘摘要报告；微观层完整打包 Trace 轨迹（历史对话、工具调用、前后状态快照），实现 Badcase 的秒级定位与排查。
5. CI/CD 持续集成与质量红线拦截：将评测中台无缝接入研发流水线，设定“核心安全用例 100% 通过、总体胜率低于阈值自动拦截合入”的质量关卡，有效防止底层大模型能力波动或 Prompt 改动导致的“智商倒退”。
6. 生产级 Badcase 闭环沉淀机制：打通线上真实用户交互与离线评测链路，将线上高频翻车案例清洗并转化为自动化回归测试集，建立“线上发现-用例固化-代码修复-回归验证”的闭环工程体系，保障核心业务规则零违背。（不要在同一个地方跌倒）

# 项目2：AI 实时语音对话智能客服
电商私域销售场景：把销售在微信/WhatsApp 的对话数据经中台清洗后建立 RAG 知识库，构建可实时语音对话的智能客服，承接商品咨询到引导下单的全流程。
1. 知识库直接消费数据中台导出的 RAG 数据，构建混合检索方案， + Int8 量化，构建 Metadata 标签过滤机制，通过TOPK、N、Rerank提升知识库召回率。
2. 接入多模态素材中心（详见项目六），命中图片、视频等素材后以「文字 + 图片 + 视频」混排分条返回，让语音/图文客服具备多模态应答能力。
3. 针对语音场景通过降维 + 精简 Limit 策略，引入 base-rerank 轻量模型，动态平衡 dense_weight 权重，在保持语义理解的同时显著提升专有名词命中率，检索速度提升 4 倍。
4. 极致优化 LLM 推理链路：固定 RAG 检索片段排序、合并 System Prompt 消息体，深度触发模型前缀缓存（Prefix Caching）与 KV Cache，将复杂 RAG 场景的首字延迟（TTFT）从 15s 压缩至 2s 内；并针对业务做模型选型与资源池优先级调优。
5. 深度优化 RTC 语音链路（ASR/TTS）：基于 ASR 实时捕获用户情感波动，配合 TTS 声音复刻实现情绪化回复；结合 FEC 前向纠错 + 自适应 Jitter Buffer，在 50% 高丢包环境下实现语音对话无感知恢复。
6. 基于 Prompt Pilot 管理提示词，构建评测集实现自动化评分与版本对比；对负样本用智能优化算法做提示词重构，并将高质量样本回流数据中台沉淀，为后续模型精调（Fine-tuning）储备语料，保障回复的准确性与一致性。
7. 接入微调后的模型作为 LLM 层（详见项目七），通过缩短 system prompt 进一步降低 TTFT；并建立 Max Token 分级控制模型，按 95% 覆盖率边界动态配置推理/输出比例，提升单请求 Token 利用率。

# 项目3：Ai数据中台　
整个 AI 体系的底座：所有跟 AI 相关的业务（客服 / 微调 / 考核 / 素材 / 直播）都从这里取数。把微信原始聊天记录加工成可训练、可检索、可考核的高质量数据资产。
1. 设计 ETL → 原始库 → 暂存区 → 人工审核 → 多下游的全链路数据流水线：从微信本地 SQLite（MSG0-5.db + MicroMsg.db）抽取消息，完成通讯录 wxid→显示名映射、群消息发送者解析、时间过滤与 (session,timestamp,content) 去重后落 raw_chats 原始库（不可变）。
2. 构建 DataFilter 内容过滤 + 脱敏引擎：按 9 级优先级分类（系统/媒体/过短/敏感/闲聊/垃圾/高价值）丢弃噪声，对手机号、身份证、银行卡、邮箱、API Key 做正则脱敏；设计多层冗余脱敏（清洗时 + 写入时 + 导出时三次），并将价格脱敏设为硬红线，杜绝微调模型泄露真实定价。
3. 实现「一键清洗」对话块构建：基于 5 分钟时间窗切分会话、合并同角色连续消息、去重，并做自动预标注（分类 / 质量分 / Q&A 提取 / 敏感标记）；高质量数据进 staging_conversations 暂存区，经人工 approve/reject/编辑后作为唯一可信数据源。
4. 训练数据导出清洗（价格脱敏、风格修复、过短过滤、过长截断、占位符清理），一份数据多格式导出：ShareGPT / Alpaca / OpenAI JSONL（供微调）与 RAG CSV（供知识库），打通项目七的微调链路。
5. 构建向量知识库下游：对 approved 数据做 embedding（DashScope text-embedding-v3）写入 knowledge_chunks，并经 LLM 提炼为结构化 knowledge_articles（场景 / 客户话术 / 推荐回复 / 置信度），同时为项目一的 RAG 检索和项目六的 AI 考核出题提供素材。
6. 中台作为数据总线对接全业务：项目五直播切片的 ASR 转写结果回流入库留存，项目六素材中心的图片/视频反向补充多模态语料，真正实现"AI 的一切都是数据"的闭环。

# 项目4：AI 直播切片 Agent　
公司有直播带货场景，把直播回放交给 AI 自动找精彩片段、配标题文案，减轻剪辑师工作；转写结果同步回流数据中台留存复用。
1. 设计「视频 → AI 找精彩片段 → 输出短视频切片」端到端 Agent，三层架构：React 19 + FFmpeg.wasm 前端、FastAPI + SQLAlchemy 2.0 后端、Groq Whisper + DeepSeek 外部 AI。
2. 关键设计浏览器内 FFmpeg.wasm 提音频：用 WORKERFS 零拷贝挂载源文件，转码为 16kHz/单声道/64kbps MP3，把 2.5GB 视频压到 ~30MB 再上传，上传体积降低 99%，用户等待从分钟级降到秒级。
3. 用 PostgreSQL 构建任务队列，API 写入 pending 秒回，Task Runner 后台协程每秒抢占一条串行执行 Pipeline，进程崩溃时启动自动重置「进行中」任务回 pending，实现零云依赖 + 崩溃可恢复。
4. 构建可观测 Pipeline（音频准备 → ASR → LLM 分析 → 切片 → 入库）：进度统一写库 + SSE 每秒读库推送，进度源唯一、断线可续、多端一致；长音频用 ffmpeg -c copy 按 25 分钟无损分段串行转录，时间戳加 offset 还原绝对时间轴。
5. LLM 分析做按 ~6000 token 分批 + 双向重叠去重（重叠 >30% 取高分项），支撑 6 小时长视频不爆上下文；内置 直播/面试/讲座场景化 Prompt，按场景切换切片时长与去重阈值；输出爆款分、推荐文案，并支持按需生成抖音风格标题与剪辑思路。
6. 导出阶段二次复用 FFmpeg.wasm 在浏览器内按 AI 时间段批量裁切打包 ZIP，后端不碰重型转码；ASR 转写结果回写数据中台留存，为后续内容分析/训练备用。

# 项目5：自媒体智能内容运营 Agent　
电商要持续产出商品图、商品介绍、宣传文案，做一个内容生成 Agent 降本增效；产出的图片直接关联到素材中心，反哺多模态知识库。
1. 基于 LangGraph 构建多阶段内容生成工作流，用 SubGraph 子图将选题、写作、配图拆为独立编排单元；通过 PostgreSQL Checkpointer 持久化状态，支持任意历史节点回滚与增量重试，将故障恢复粒度从整图细化到单节点。
2. 设计 MetricsContext 上下文管理器做 LLM 全链路追踪，采集各节点 Token 消耗、推理延迟、错误率，结合火山引擎定价模型完成成本核算，为模型选型提供数据支撑。
3. 实现 SSE 流式输出与 LangGraph astream_events 深度集成，监听 on_chat_model_stream 捕获 Token 级实时流，配合前端 ReadableStream 将感知 TTFT 降低 60%，并保证流式/非流式下 Checkpointer 数据结构一致。
4. 针对配图批量生成做异步并行优化：asyncio.gather + run_in_executor 将同步 API 封装为协程并发执行，引入指数退避重试（1s→2s→4s）应对服务抖动，整体生成耗时缩减 70%。
5. 构建多模型动态路由：简单任务走轻量 Flash 模型、复杂任务走旗舰模型，配合 with_structured_output 做 Pydantic Schema 强约束，并用 JSON Mode + 手动解析解决结构化输出与 Token 统计不兼容问题，降低 40% 推理成本。
6. 设计环境变量驱动的 Mock 开关体系（llm/image/checkpointer）解耦外部服务，配合 Swagger UI 可视化评测与 Ngrok 公网映射，将本地调试效率提升 3 倍；接入 LangSmith + structlog + request_id 实现全链路可观测，问题定位从小时级压缩到分钟级。
7. 基于 SlowAPI 接口限流 + 指数退避重试 + 熔断降级 优雅关闭保障容器化高可用；生成的商品图直接写入素材中心（项目六），经离线增强后成为 AI 客服的多模态回复素材，形成"生成即沉淀"的闭环。

# 项目6：基于 MCP 协议的多 Agent 共享服务集群
随着 AI 项目越来越多，做架构层面的统一收口：把 LLM 网关、RAG、记忆、Prompt 抽成共享基础设施，让所有业务（含数据中台）复用同一套底座。
1. 将 LLM 网关、RAG 检索、会话记忆、Prompt 管理抽离为 4 个独立 MCP Server，经 Streamable HTTP 暴露标准化 Tool/Prompt 原语，新业务接入仅需写 Agent 编排层。
2. 设计 REST → MCP 协议桥接网关，基于 FastAPI 构建四层中间件链（认证 → 日志 → 配额 → 路由），用 Trace ID 全链路追踪；内置 MCP Client Manager 管理短连接，按项目维度做 API Key 认证与 Token 配额计量，保障多租户安全隔离与成本管控。
3. 构建统一 LLM 网关，实现逻辑模型名 → Endpoint 路由（auto/pro/lite），YAML 配置热切换业务无感；Embedding 兼容火山引擎 text 与 vision 两种向量化路径，Token 消耗统一回传配额模块扣减。
4. 实现多租户 RAG 服务：基于火山引擎 Viking DB 按 project_id 划分独立 Collection 做物理隔离，按 Markdown 标题层级 + 段落边界语义切分，新项目调 ingest_document Tool 即可自助接入。
5. 设计双层记忆架构：对话记忆按 project_id + session_id 隔离支持最近 N 轮召回；用户画像按 user_id 跨项目共享，基于 PostgreSQL UPSERT (ON CONFLICT DO UPDATE) 幂等写入，客服 Agent 自动提取用户事实（过敏/预算/偏好），写作 Agent 即时读取，实现跨项目用户认知同步。
6. 基于 MCP 原生 Prompt 原语构建模板中心，YAML 定义参数 Schema、服务端渲染为 PromptMessage，模板修改即时生效无需重启，实现提示词工程与业务逻辑解耦。
7. 实现 Agent 七步编排流水线（召回历史 → 读画像 → 检索知识 → 渲染 Prompt → LLM 推理 → 存记忆 → 提取事实），全部经 GatewayClient 统一调用，Agent 无状态、状态下沉到共享服务；各服务独立构建 Docker 镜像部署至阿里云 Serverless（FC/SAE），按拓扑分层发布、灰度 + 秒级回滚，SIGTERM 优雅终止保障在途请求不丢。

# 项目6.1：AI Agent 质量基础设施与平台治理 （啰嗦版）（可以把MVP集群这个项目删掉，可以理解是MCP集群项目的升级版本）
1. 构建评估平台三件套，把质量从"人工抽查"升级为强制门禁：评测集资产化（真实对话日志脱敏沉淀 + 事故用例 + 红队对抗用例，pgvector 查重防同义题堆积）；分三层定位问题（RAG 层看检索命中率、模型层看忠实度、Agent 层看任务完成率与轨迹质量）；打分方法按成本阶梯组合——规则断言（格式/来源引用/禁词）→ Embedding 语义相似度 → LLM-as-Judge，200 条用例全量回归 20 分钟内完成，单次成本控制在几十元，使"每次改动全量回归"在经济上可行。
2. 设计四要素变更触发的回归门禁，拦住一次典型的无声回退：将 prompt / 模型端点 / 知识版本 / 工具描述任一变更纳入自动触发，报告按业务场景（suite）拆分对比基线，规则为"任一场景跌幅 > 5 分或总均分跌幅 > 2 分即阻断"。实测一次降本切换模型时总均分仅跌 3 分、但投诉安抚场景跌 12 分，据此将单一逻辑模型名拆分为按场景分流（简单咨询走 lite、情绪场景走 pro），最终推理成本下降约 30% 且质量持平——门禁产出的是"该怎么改"而非"不许发"。
3. 实现 Judge 可信度治理：Judge 与被测模型强制异厂（规避自我偏好偏差），提示词与模型在考核周期内锁定，季度抽样人工校准并留存校准记录；门禁判据只用"相对跌幅"不用"绝对分数"，使系统性误差在做差时抵消。
4. 设计沿数据流布防的四道护栏关，全部长在平台组件上、业务无法绕过：输入关（规则禁词 → 云内容安全 API → Embedding 攻击话术库相似度，后两者并行 + 热问题结果缓存，合计约 40ms）、检索关（按最终用户 user_groups 而非 Agent 身份过滤 ACL）、执行关（工具 R1/R2/R3 分级，R2 注入幂等键、R3 强制挂起人工确认）、输出关（流式分段审核 + 命中即中断替换兜底话术）。四道关合计开销约 110ms，占端到端时延 5% 以内。
5. 确立护栏的两项工程纪律：策略分为全局强制层（内容安全、注入检测、品牌红线，租户不可关闭）与租户叠加层（只能更严不能更松）；护栏本身纳入评估管理，以拦截率与**误拦率（目标 < 0.1%）**作为自身质量指标，误拦样本每周回流调阈值——避免在投诉压力下直接关闭规则。降级方向按 Agent 风险级分化：低风险 fail-open，对外高风险 fail-close。
6. 建设网关治理与成本归因平面：虚拟 Key 体系（库内只存 sha256、前缀可读便于排查、expires_at 防僵尸 Key、last_used_at 识别闲置），三级配额（租户 / 项目 / 单 Key）隔离失控循环；主链路零数据库查询——配置启动载入内存、限流与配额计数走 Redis、调用流水异步批量落库；据此实现按项目/应用的 Token 与费用归因，并配置成本速率突增告警（5 分钟消耗超日均同期 5 倍），把失控循环的发现从"月底账单"提前到分钟级。
7. 拆分三类可观测数据并统一查看入口：计量流水入 PostgreSQL（供财务对账，长周期保留）、运行日志入 SLS（30 天，按 ScheduledSQL 定时聚合出指标与告警，不额外引入 Prometheus）、请求正文默认不落盘（隐私与存储双重考虑）；建立 trace_id / request_id / upstream_id 三级 ID 贯穿，网关自身耗时与上游耗时分离记录，使"这次慢是谁的锅"与"向供应商申诉"都有据可查，问题定位从小时级降至分钟级。
8. 建立红队即服务与双向闭环：平台侧维护注入库、诱导话术库、越权库、边界话题库，对外场景 Agent 上线前必过；攻破的用例回流评测集、拦截的模式回流攻击库向量，使评估与护栏互为素材来源，形成质量数据的复利。
# 项目6.2：AI 原生研发协作范式（啰嗦版）
全员用上 AI 编程工具后出现产能悖论：写代码不再是瓶颈的那一刻，对齐、约定、评审三个旧瓶颈同时爆炸。这个项目把协作的对象从"代码"上移到"意图与上下文"。
1. 建设 Context as Code 资产层，统一 Agent 的认知基线：将团队架构约定、目录归属、禁区清单写入 AGENTS.md 与 .cursor/rules，把发布流程、数据库迁移规范、排查手册写成 Agent 可执行的 Skills；全部与代码同仓同版本、走 PR 流程演进。关键认知是上下文文件的读者从"新员工"变成"每一个 Agent 会话"，消费频率高三个数量级，因此由人工维护而非 LLM 自动生成，并在每轮 Retro 沉淀新模式形成复利回路。
2. 推行 Spec 驱动开发（SDD），把返工成本预付成对齐成本：确立 Propose → Apply → Verify → Archive 生命周期，团队评审对象从代码前移到规范；spec 与实现放在同一个 PR 内评审——人看意图与架构，AI 校验实现与 spec 的一致性；增量 spec 归档进活规范库，成为后续所有 Agent 的上下文。同时明确分寸：原型探索期不强制 spec，以"是否跨人、是否长期维护、是否有验收争议"三条作为切换判据。
3. 建立并行编队的隔离与切分纪律：用 git worktree 为每个 Agent 分配独立工作目录，把文件互相覆盖问题下沉回 git 早已解决的分支问题；并行前强制三项独立性检查（文件互斥、接口契约稳定、范围可一句话界定），任一不满足即串行。实践结论是并行瓶颈不在 Agent 数量而在任务切分，稳定甜蜜点为单人 3–5 个 Agent，真正的上限是代码库吸收并行变更的能力（模块边界清晰度与测试覆盖）。
4. 重构质量门禁，解决生成远快于评审的产能倒挂：确立三层分工——人评审 spec 与架构决策（左移到实现之前）、AI Reviewer 做代码初审、自动化门禁（测试 / 类型 / lint / spec 一致性）守底线且全绿才有资格进人审；同步将分支模型从 Git Flow 回摆到 Trunk-Based + 短生命周期分支，适配 Agent 小步快跑的产出形态。核心判断是：AI 把生成成本降了一个数量级，验证成本必须同步降一个数量级，否则门禁只是在积压风险。
5. 对 Agent 类产品建立第二套门禁：Evals 即测试（与项目八打通）：prompt、评测数据集、eval 脚本全部纳入 git 版本管理，改 prompt 必须跑 eval 回归如同改代码必须跑测试；以 trace 观测替代传统日志，完整还原一次生成经过的模型、检索与工具步骤，解决"一次 prompt 优化让质量无声回退、两周后才从投诉中发现"这类问题。
# 项目7：多模态素材中心 & AI 销售考核系统　
两件事一条数据线：素材中心统一管理商品图/详情/视频，为 AI 客服提供多模态回复能力，同时补充数据中台；中台导出的高质量知识又驱动 AI 销售考核，替代过去的人工培训。
A. 多模态素材中心（图片 / 视频 → 可被语义命中的多模态知识库）
1. 设计统一向量底座 rag_assets：text/image/video 三模态共用一张表（pgvector 1024 维 + HNSW vector_cosine_ops），一条 SQL 跨模态召回；核心理念是不向量化媒体本身，而向量化其「检索文本」retrieval_text（"这张图/视频能回答什么问题"），与用户文本提问天然对齐。
2. 实现人工即时命中（manual）路线：图片/视频上传时人工维护标题/描述/标签/分类，拼接为 retrieval_text 经 text-embedding-v3 入库即可被命中；隐私红线为命中返回打码版 TOS URL。
3. 实现离线机器增强（enriched）路线：在同一行上用 OCR（RapidOCR）+ VLM（qwen-vl） 补图片文字与看图描述、用 ASR + LLM 摘要补视频口播，人工内容在前、机器内容追加，重写 retrieval_text 并重新 embedding，召回相似度从 ~0.38 提升至 ~0.71；按 (source_table, source_id) UPSERT 幂等可反复回扫。
4. 设计长视频按 ASR 时间戳分段为多条 rag_assets，media_url 携带 #t=秒数，命中后前端播放器直接跳转到精彩片段；统一应答按「文字必发、图≤3、视频≤1」混排，阈值递增（text 0.35 < image 0.40 < video 0.42）。
B. AI 销售考核系统（替代人工培训与考核）
5. 实现 LLM 自动出题：消费数据中台产出的 knowledge_articles/knowledge_chunks，按场景分类 + 置信度取素材，以「资深考官」角色（temperature 0.7）生成简单/中等/困难分级的开放式场景题与参考答案。
6. 实现 LLM 自动评判：以「资深评审专家」角色（temperature 0.3 保稳定）从实战性、需求把握、销售策略、话术自然度、红线检查五维度逐题打分，按「平均分 ×10」映射百分制，支持人工二次复核校准。
7. 针对知识库膨胀到十万级的演进，设计 RAG 出题方案：模糊请求先由 LLM 规划主题 → 多轮向量检索（pgvector/Milvus）→ MMR 去重保多样性，解决固定 top-30 导致题目重复、长尾素材浪费的问题。

# 项目8：基于聊天数据的大模型微调
为了让 AI 客服回复更像真人，基于数据中台导出的 SFT/DPO 数据微调豆包模型，再回灌到项目一的客服系统。
1. 微调语料直接来自数据中台：消费中台 approved 的 ShareGPT/OpenAI 格式数据，并将对话分流为两套——SFT 数据（保留多轮上下文学销售话术风格）与 RAG 知识库数据（提炼课程、价格、优惠等结构化知识），践行"微调管风格、RAG 管知识"的职责分离，知识更新只改知识库无需重训。
2. 采用「本地小模型验证 + 云端大模型训练」两阶段策略：本地 LLaMA-Factory + Qwen2.5-7B-Instruct 做 QLoRA（rank=64, alpha=128, lr=2e-4），单卡 RTX 4090 约 40 分钟一轮快速验证数据质量；通过后上传火山引擎方舟对豆包 1.6 做生产级 LoRA（rank=32, lr=1e-5），按模型规模等比缩放超参，风格一致性人工盲评从 2.1 提升至 4.3（5 分制）。
3. 规划 SFT → DPO 两阶段训练路径：SFT 解决"从不会到会说"的风格模仿；DPO 对同一问题采样多条回复，由销售主管标注 chosen/rejected 偏好对训练优劣区分，解决"会说但说不好"；选 DPO 而非 RLHF 是因其跳过奖励模型训练，在偏好数据有限（几百条）时更稳定、成本更低。
4. 构建 Embedding → 向量检索 → Rerank 三阶段 RAG Pipeline：火山引擎 Embedding 向量化 + 向量检索 top-20 粗召回，引入 Cross-Encoder 精排取 top-5，解决双编码器在语义相近文档上区分度不足问题，知识命中率从 72% 提升至 89%。
5. 微调后的模型作为 LLM 层接入项目一 RTC 实时语音链路（客户语音 → ASR → RAG → 微调 LLM → TTS → 语音回复），通过微调缩短 system prompt 降低 TTFT，在实时对话场景下保障体验，完成"数据中台 → 微调 → 客服"的回路闭合。



# 项目9：商品交易自进化Agent ——Harness与Loop Engineer 架构设计
从零设计并实现一套模型无关、工具可插拔的 Agent 运行时底座(Harness),支撑可自主决策、可自我进化的智能客服 Agent。架构范式对齐 Claude Code,核心解决"如何用一个通用循环 + 标准化工具承载复杂多变的业务,而非堆砌流程编排"。

---
一、Harness 架构底座:模型无关、工具可插拔的 Agent 运行时
- 双抽象 + 注册表解耦:以 LLMProvider 抽象隔离大模型、Tool 抽象 + 注册表承载能力,Loop 引擎只依赖接口、与具体模型/工具零耦合;新增模型仅实现一个 chat() 适配器,新增能力仅登记一个 Tool,业务与循环代码零改动。
- 模型热切换:配置驱动在「离线 Mock 桩」与「真实大模型」间一键切换——Mock 保证 CI/演示可离线复现,ARK 接入真实豆包,同一套 Loop 无差别运行。
- 标准化消息协议:内部统一采用 tool_call / tool_result 配对结构,与 OpenAI / Anthropic function calling 同构,provider 层近乎零转换成本,可平滑接入任意兼容模型;相比早期自定义格式需在适配层伪造调用配对,重构后彻底消除该耦合。
二、Agent Loop 架构:模型自主决策的推理-行动循环
- Model-driven 自主循环:实现"推理 → 工具选择 → 调用 → 观察 → 再决策 → 终止"闭环,决策权完全交给模型,意图识别隐式融入工具选择,去除独立意图分类模块——这正是 Claude Code 式 Agent 与传统 Workflow 的架构分水岭。
- 单步多工具并行:重构 LLMDecision 支持一步并行发起多个工具调用并批量回填观察结果,提升复杂问题处理效率(对齐主流模型的 parallel tool use)。
- "错误即上下文"自纠错:工具异常 / 未知调用被捕获并转为 observation 回填,由模型自我纠正而非中断会话,显著提升鲁棒性。
- 确定性边界护栏:内置最大步数 + 超时双重限制防止死循环与失控,超限自动降级转人工,保证服务可预期。
- 全链路可观测:结构化记录每一步"思考-调用-结果"Trace,前端可视化 Agent 决策链路,支撑演示与线上排障。
三、AI 自进化:示范学习 + 人在环自纠错闭环
- 示范学习替代微调:业务专家以「问题 + 标准答案 + 套路原因」对话式教学 → 样本入库 → LLM 自动归纳"套路总纲" → 注入系统提示词驱动真实回复。相比微调,轻量、可解释、改完即时生效,更契合业务话术高频迭代。
- 语义泛化,举一反三:服务时召回全量样本交大模型语义精判,换问法 / 相似意图自动命中套路,未教过且无把握的问题自动转人工,守住事实红线。
- 状态合并(可控进化):套路总纲支持人工改写并持久化,重归纳时以人工版为基底增量融合新样本(冲突以人工为准),坚持单一数据源、杜绝规则漂移。
- 自纠错闭环 + 点评式教学:答不上 → 工单 → 专家补充 → 入库 → 下次答对;并支持实测中对回复提"纠偏意见",Agent 即时重答、满意后一键固化为样本并自动合并进总纲。
- 提示词分层治理:业务铁律 > 套路总纲 > 召回样本话术,分层拼装、优先级明确,保障报价等高风险动作可控。
