# AI 自媒体运营项目：简历表述与面试主线

按原来的八条技术重点组织，弱化夸张的百分比，重点突出设计方法和解决的问题。这里是面试表达稿；详细原理和教学代码见 [简历重点理解](./简历重点理解.md)。

**项目名称：AI 自媒体内容运营助手**

**技术栈：Python、FastAPI、LangGraph、PostgreSQL、LLM API、SSE、Vue、LangSmith。**

面向教育培训公司的自媒体内容生产场景，围绕“选题推荐—人工选择—文案生成—人工审核—配图生成”搭建工作流，支持审核反馈驱动的内容修订与过程追踪。

### 1. 工作流与恢复

> 1. 基于 LangGraph 构建多阶段内容生成工作流，采用 SubGraph 子图模式将选题、写作、配图拆分为独立编排单元；通过 PostgreSQL Checkpointer 实现状态持久化，支持任意历史节点回滚与增量重试，将复杂流程的故障恢复粒度从整图级别细化至单节点级别。

**通俗解释：**把选题、写作和配图拆成工序，用 State 传递工作单，用检查点记住执行进度。人工恢复、历史回放、失败重试是三个相关但不同的动作。

### 3. SSE 流式文章

> 3. 实现 SSE 流式输出与 LangGraph astream_events 深度集成，通过监听 on_chat_model_stream 事件捕获 Token 级别实时流，配合前端 ReadableStream 解析，将用户感知的首字延迟（TTFT）降低 60%；同时保证流式与非流式模式下 Checkpointer 数据结构一致性。

**通俗解释：**后端监听模型片段并通过 SSE 推给浏览器，前端流式解码和缓冲解析。首字延迟表示多久能看到第一段内容，不等于整篇文章生成时间。

### 4. 并发配图与重试

> 4. 针对图片批量生成场景实现异步并行优化，通过 asyncio.gather 配合 run_in_executor 将同步 API 封装为协程，多张配图生成由串行改为并发执行；引入指数退避重试策略（1s→2s→4s），有效应对 LLM 服务抖动，整体生成耗时缩减 70%。

**通俗解释：**多张图一起请求以重叠网络等待；同步 SDK 用线程池适配，原生异步直接 await。失败后按 1、2、4 秒等间隔再尝试，并限制次数。

## 八条项目重点（理解与表达版）

1. **工作流编排与状态恢复**：基于 LangGraph 构建多阶段内容生产工作流，采用 SubGraph 拆分选题、写作与配图等编排单元；通过 PostgreSQL Checkpointer 保存执行状态，支持人工中断恢复、历史状态回放及失败阶段重试，避免重复执行整个流程。
2. **节点指标与成本分析**：设计 MetricsContext 上下文管理器，统一采集节点耗时、模型调用用量及异常信息；结合不同模型的输入、输出 Token 单价进行成本估算，为模型选型和调用优化提供依据。
3. **文章流式输出**：将 SSE 与 LangGraph astream_events 集成，监听 on_chat_model_stream 事件向前端推送文本片段，配合 ReadableStream 实现文章逐步展示，改善长文生成时的等待体验，并统一流式与普通调用的状态管理。
4. **配图并发与请求重试**：使用 asyncio.gather 并发执行多张配图生成，对阻塞式 SDK 使用 run_in_executor 隔离；结合指数退避与重试上限处理临时性服务故障，减少串行等待并提高批量生成的稳定性。
5. **模型路由与结构化输出**：根据任务类型和复杂度分配模型，简单选题与信息提取使用轻量 Flash 模型，长文写作使用 Doubao 等标准模型；结合 Pydantic、with_structured_output 及 JSON 解析兜底处理输出格式，并保留原始响应中的用量信息。
6. **Mock 与开发联调**：设计环境变量驱动的 llm_mock、image_mock、checkpointer_mock 开关，在真实服务与模拟实现之间切换；结合 Swagger 调试接口，通过 Ngrok 临时提供外部联调入口，减少开发对外部服务和额度的依赖。
7. **可观测性与问题定位**：结合 LangSmith 观察节点路径、模型调用与阶段耗时，使用 structlog 输出结构化日志，通过 request_id、thread_id 关联请求和工作流，辅助定位节点失败、生成缓慢及用量异常。
8. **限流、熔断与服务生命周期**：基于 SlowAPI 设置接口级限流，结合熔断与降级保护下游模型服务；配合健康检查和优雅关闭管理连接池等资源，提升外部服务抖动时的系统稳定性。

## 面试介绍顺序

不要一开始逐条念技术名词，按这条线介绍：

> 项目服务教育培训公司的内容运营。运营输入方向后，AI 推荐选题，人工选择后生成文章，审核不通过就根据反馈重写，通过后生成配图。我的技术重点分三层：第一层用 LangGraph 和 PostgreSQL 解决流程与恢复；第二层用 SSE、异步并发和模型分工改善生成体验；第三层用指标、日志、Mock、限流和熔断提高调试效率与运行稳定性。

## 八条分别会被问什么

| 重点 | 常见追问 | 回答抓手 |
| --- | --- | --- |
| 工作流 | 为什么用图？如何暂停、回退和恢复？ | State、Node、SubGraph、interrupt、Command、checkpoint |
| 指标 | 统计什么？耗时在哪里结算？成本怎么算？ | with 进入/退出、usage、输入输出分别计价 |

| 可观测性 | 日志和 trace 有什么区别？ID 怎么关联？ | 请求日志、节点链路、metadata、隐私控制 |
| 服务保护 | 限流、重试、熔断有什么不同？ | 入口控制、失败再试、故障隔离、降级 |
